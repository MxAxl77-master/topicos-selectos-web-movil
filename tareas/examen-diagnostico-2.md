## 1. Metodologías

¿Cuál es la diferencia principal entre una metodología de desarrollo tradicional (como Cascada) y una metodología ágil (como Scrum) frente a los cambios en los requisitos?

La metodología de Cascada sigue un orden y es ams dificil realizar cambios una vez avanzado el proyecto, en cambio, Scrum permite realizar cambios durante el desarrollo del proyecto, es mas flexible.

## 2. Requerimientos

Explica la diferencia entre requerimientos funcionales y no funcionales, dando un ejemplo de cada uno aplicable a una plataforma web.

Los funcionales son aquellos que es sistema deberia de hacer, por ejemplo, que el usuario pueda iniciar sesión, los no funcionales son mas de como la plataforma web deberia de funcionar, por ejemplo, que la pagina cargue mas rápido.

## 3. Arquitectura

Describe el modelo Cliente-Servidor y explica brevemente cómo se comunican el frontend y el backend en una aplicación web moderna.

El modelo cliente-servidor es cuando una pagina web manda solicitudes a un servidor y se le regresa información, el frontend es lo que ve el usuario y el backend es basicamente lo que no ve el usuario y en donde esta toda la procesamiento de datos para el funcionamiento de la pagina web.

## 4. Bases de Datos

¿En qué escenarios recomendarías utilizar una base de datos relacional (SQL) frente a una no relacional (NoSQL) para el almacenamiento de datos en una aplicación?

Yo usaría SQL cuando tengo bien organizados los datos y hay muchas relaciones entre si, y yo usaría NoSQL cuando tengo datos que pueden cambiar o que no haya relaciones entre ellos o que sean datos diferentes.

## 5. APIs

¿Qué es una API REST y qué papel fundamental juega en la integración entre una aplicación móvil y los servidores (backend)?

Una API REST es una forma de comunicación entre aplicacion y servidor, por ejemplo una aplicacion pide a las APIs los datos de un usuario y el servidor se los manda en un JSON.

## 6. Control de Versiones

Explica la importancia de utilizar Git en un equipo de desarrollo de software y describe brevemente qué es un "merge conflict" (conflicto de fusión).

Git sirve para llevar un registro de los cambios del código y permite el trabajo colaborativo, un merge conflict es cuando dos persoans tocan o modifican la misma parte de un codigo y git no sabe con que cambio quedarse.

## 7. Pruebas

¿Qué son las pruebas unitarias (unit testing) y por qué son cruciales para asegurar la calidad del software antes de su paso a producción?

Las pruebas unitarias sirven para probrar partes pequeñas del proyecto, son importantes ya que ayudan a encontrar errores antes de que todo el programa se publique y así evitamos problemas.

## 8. POO

Define los conceptos de encapsulamiento y polimorfismo de la Programación Orientada a Objetos, y menciona cómo ayudan a crear un código más mantenible.

El encapsulamiento es el proteger o controlar los datos de un objeto para que no se modifique de cualquier manera, el polimorfismo permite utilizar metodos parecidos pero que pueden tener un comportamiento diferente, esto nos ayuda a organizar mejor el código.

## 9. Patrones de Diseño

¿Qué es el patrón de arquitectura Modelo-Vista-Controlador (MVC) y cómo ayuda a organizar el código en el desarrollo de software?

MVC divide una aplicación en Modelo, Vista y Controlador, el modelo trabaja con los datos, la vista es lo que ve el usuario y el controlador maneja las acciones, esto ayuda a que el codigo esrte ordenado.

## 10. Seguridad

Explica la diferencia técnica entre "autenticación" y "autorización" en el contexto de seguridad de una aplicación.

La autenticación sirve para comprobar quien eres, por ejemplo al momento de iniciar sesion, la autenticacion es lo que determina que cosas puedes hacer despues de iniciar sesion, por ejemplo un administrador que tiene permisos que un usuario normal o con otro rol no tiene.
